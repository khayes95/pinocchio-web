Pinocchio

01

The access problem

The models doing the most consequential work are closed. Call GPT-5, Claude, or Gemini and you get text and a bill, nothing else.

Every standard uncertainty method needs an internal the endpoint withholds: token log-probabilities, repeated sampling, ensembles, activations, or a round of fine-tuning. None of it is reachable through an API, so the usual toolkit does not run on the systems that most need one.

Pinocchio reads the one signal always returned, the response text. Given a question Q and an answer A, a small external calibrator returns P(correct) in a single forward pass.

It never touches the target: no logits, weights, sampling, or fine-tuning. Because it consumes text alone, a new model is just new text, so one instrument scores GPT-5, Claude, Gemini, and open models through a single interface.

Fig. 01-Athe sealed endpoint, one channel out
Everything a log-prob method would inspect is sealed. Pinocchio reads only the text the endpoint returns, the one channel a black box leaves open.
The obvious black-box fallback, asking the model how sure it is (verbalized confidence), is available but weak: about 0.65 AUROC against roughly 0.88 for Pinocchio on the same head-to-head set.
02

One calibrator, seven sources

We do not fit one estimator per model. A single calibrator trains jointly on responses from seven source models, four frontier systems plus three capability-diverse ones.

On held-out frontier responses it reaches 0.862 AUROC separating correct answers from incorrect, reading nothing but the text.

The mixture is deliberate. Train only on models that are almost always right and the calibrator rarely sees a confident failure, so it learns little.

Spanning a range of capability shows it confident successes and confident mistakes, which is what lets P(correct) tell the two apart.

03

Transfer to models it never saw

The same calibrator, with no target labels and no retraining, scores 12 unseen models across 7 organizations at 0.815 mean AUROC. Four are named below, spanning Google, Mistral, Meta, and DeepSeek. That is only a modest drop from the 0.862 on the models it was trained on, and far above simple baselines like response length.

Trace 03-Azero-shot transfer, no target labels
One calibrator, trained on the seven sources, applied unchanged to models from other organizations. It reads uncertainty from text, so an unseen model is just unseen text.
04

Why it transfers: capability diversity

Transfer is earned by the choice of sources, not automatic. Train the calibrator only on frontier models and mean transfer AUROC is 0.649, near chance on some targets.

Add capability-diverse sources, weaker and mid-tier models that fail in visible, varied ways, and the same evaluation rises to 0.814.

The reason is what the calibrator gets to observe. Frontier-only data is nearly all confident successes, so it never learns the texture of a confident mistake.

Diverse sources supply exactly those failures. Watching how wrong answers read across the capability range is what teaches the calibrator to generalize to models it has never scored.

Trace 04-Amean transfer AUROC by training mixture
Same targets, same evaluation. The only change is who the calibrator trained on. Confident failures, supplied by diverse sources, are what carry over.
05

Correct it with about 100 labels

Ranking transfers well out of the box, but the absolute probabilities on a brand new target can drift. That is cheap to fix.

About 100 labeled responses from the new model recalibrate the instrument, cutting expected calibration error (ECE) from 0.26 to 0.06 while preserving the ranking the calibrator already learned.

In a reliability diagram, a perfectly calibrated instrument sits on the diagonal: stated confidence equals observed accuracy.

Before recalibration the curve sags below the line, overconfident. After roughly 100 labels it snaps back onto the diagonal.

Trace 05-Areliability, before and after about 100 labels
A small, cheap labeling budget snaps the probabilities back onto the diagonal without disturbing the ordering.
06

How it reads

The calibrator is a small model prompted for a binary verdict on (Q, A). In one forward pass it reads its own next-token logits for the two option tokens, ii (Yes) against i (No), and returns their softmax as P(correct):

$$P(\text{correct}) = \frac{e^{z_{\text{Yes}}}}{e^{z_{\text{Yes}}} + e^{z_{\text{No}}}}$$

Those are the calibrator's logits, not the target's. The target is never inspected, only its text. One pass, no sampling, no fine-tuning of the target.

Against the obvious black-box baseline, asking the target how confident it is, Pinocchio wins by a wide margin: about 0.88 AUROC versus about 0.65 for verbalized confidence. A compact, CPU-friendly checkpoint is also released for lightweight deployment.

07

Wiring it in

quickstart.pypython
from pinocchio import Pinocchio

# One calibrator scores any black-box model, from the response text alone.
judge = Pinocchio()   # downloads the 0.8B adapter (~25 MB) on first use

answer = openai.chat.completions.create(
    model="gpt-5.6",
    messages=[{"role": "user", "content": question}],
).choices[0].message.content

p_correct = judge.score(question=question, answer=answer)   # single forward pass, no logits or weights

if p_correct < 0.5:
    escalate(question, answer)          # route low-confidence output to a human

Same interface across model families: swap model="gpt-5.6" for a Claude, Gemini, or local response and call judge.score unchanged. A new distribution can be recalibrated with about 100 labels (Platt or isotonic).
