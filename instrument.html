Pinocchio

A lie detector for language models. It reads only the text of a response and returns the probability the answer is correct, with no log-probs, no samples, no weights. One judge scores even the newest black-box systems it never saw: Claude Opus 5, GPT-5.6, Kimi 3, Fable 5.

The brief

In high-stakes settings you need not only accurate models but honest uncertainty per prediction. The usual tools (log-probabilities, sampling, fine-tuning) are exactly what a closed API withholds.

Pinocchio is a suite of 8B checkpoints that assigns an uncertainty estimate to any model's prediction using only the text of the response. Text LLMs and vision-language models alike.

It transfers across model families without retraining and plugs into an existing pipeline in two lines. We train it on a curated, difficulty-spread mixture of hard benchmarks so it sees confident successes and confident failures.

Against black-box baselines it wins on calibration and discrimination, and generalises to models whose responses it never trained on.

03

Wiring it in

quickstart.pypython
from pinocchio import Judge

judge = Judge.from_pretrained("KevinDavidHayes/pinocchio-text-8b")

# Score any model's response: OpenAI, Anthropic, vLLM, local HF, anything.
response = openai.chat.completions.create(model="gpt-5.6", messages=[...])
p_correct = judge.score(question, response.choices[0].message.content)

if p_correct < 0.5:
    log("Low confidence. Flag for human review.")

Same API for VLMs: pass an image alongside the question/response and load pinocchio-vlm-8b.

Units

Unit I

One transferable judge

A single 8B calibrator hits 0.878 AUROC on the hard suite and transfers zero-shot to 16 unseen models across 9 orgs, the four newest frontier systems among them.

Unit II

Text and vision, one checkpoint

Scores text-LLM and vision-language responses at comparable AUROC, so there is no separate per-modality model to run.

Unit III

Small, and correctable

The 0.8B model keeps 99% of the 9B AUROC, and about 100 labels halve the calibration error on a new model.

05

How it reads

Given a question Q and candidate answer A, the judge is prompted for a binary verdict and reads P(correct) from the softmax over the next-token logits for ii (Yes) vs i (No):

$$\hat p(\text{correct})=\frac{e^{z_{\text{yes}}}}{e^{z_{\text{yes}}}+e^{z_{\text{no}}}}$$

It never touches the target model's internals, only its text. Post-hoc temperature scaling sharpens calibration while preserving ranking.

Question: {Q} Answer: {A} Is the answer correct? (i) No (ii) Yes

Training mix: 15+ text benchmarks (GSM8K, BBEH, SimpleQA, GPQA, OmniMath, HLE, …) and 8 vision-language benchmarks (MathVista, MathVerse, CharXiv, MMMU, HallusionBench, VSR, …).
